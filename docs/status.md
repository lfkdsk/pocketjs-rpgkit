# Feature status

What Pocket RPG Kit can do today, area by area.

The implemented highlights can be explored together in the
[`examples/showcase` feature gallery](../examples/showcase/README.md).

- **Done**: on `main` and covered by tests.
- **Partial**: works within the limits noted.
- **Planned**: not on `main` yet. "In progress" means someone is working on it now.

The links point to where each feature is described in detail.

## Event system

| Feature | Status | Notes |
| --- | --- | --- |
| Event pages with `action`, `playerTouch`, `eventTouch`, `autorun` and `parallel` triggers; common events | Done | [The 72 commands](../README.md#the-72-commands); `eventTouch` fires when the player walks into a blocking event or the event's own step is refused by the player (RPG Maker Event Touch), see [Event Touch](../src/engine/README.md#event-touch) |
| Loops (`loop` / `break`) and labels (`label` / `jumpLabel`) | Done | `break` leaves the innermost loop from nested `if`/`choices`/`battle`/`scene` blocks; a loop that never waits yields after 1,000 steps per tick instead of stalling. `jumpLabel` goes to the first matching label in the same page or common event, at any nesting depth, entering or leaving branch blocks unconditionally; a missing label is a no-op. "First" follows MV's flat source order: the importer stamps each label with its source ordinal and the resolver picks the lowest, so a Battle Processing list resolves Win/Escape/Lose and a reversed (Gold ≤/<) condition keeps its original Then/Else label order even though the importer swaps the branches. Hand-authored lists use tree-walk order, with battle branches visited Win/Escape/Lose. A jump that leaves a battle/scene result branch — to a label in the same branch, the parent list, a sibling, or an outer scope — keeps the branch's completion transfer: it hangs on the frame as an ordered `onDone` queue (not the program), and a jump that pops the frame relocates the queue to the landing frame, so completions fire innermost first however the branch is left (even when its last command pushed a child frame). A cross-map transfer rebuilds the interpreter for the new map, so the old map's fibers end and any completions still queued on them are discarded: of nested cross-map completions only the innermost takes effect. `exit`/`erase` inside a result branch ends the whole event and abandons the queued completion with the fiber. See [Loops](../README.md#loops) and [Labels](../README.md#labels) |
| Dialog: typewriter text, choices with 2–8 options (scrolling past 4) and a cancel branch | Done | |
| Long text is never cut: dialog continues on further pages, options and labels wrap | Done | A message longer than its box (four rows in the default box, two in a Tuxemon-size corner or side box) takes one confirm per page; pages are decided when the box opens and kept in reducer state (same at every rate and after rewind), cut at the 480x272 design size. Choice prompts and options, shop names, icon-choice labels, battle menus, the battle message band and save-menu strings wrap and their boxes grow; a fixed battle command cell wraps to two rows, then steps down from 12 px to 10 px (one or two rows), and only a label that two 10 px rows cannot hold is clipped, with the focused cell scrolling it sideways. Limits: pages need GameView's paginator (a bare `DialogBox` or headless session shows one page); 10 px is the only smaller size, and an unfocused clipped cell shows its first characters. See [Long text is never cut](../README.md#long-text-is-never-cut) |
| Chinese (CJK) text in dialog, choices, shops, battle menus and the save menu | Partial | Rows break between CJK characters with simplified kinsoku, Latin words and numbers stay whole, labels wrap at their pixel width, the typewriter steps by code point. A per-app Noto Sans CJK SC subset holds only the characters the app displays (`tools/cjk-font.ts` reads its decoded strings, escapes included), and its license ships inside the pak and beside web and desktop builds. The preview and Studio play-test draw Chinese from a budgeted face (GB2312 level 1 and punctuation) baked at load. Latin-only apps bake no CJK atlas. Limits: Simplified Chinese glyphs only; every used font slot carries every character (about 776 bytes each in the atlases at density 1, about 1,552 resident on PSP, plus 138/276 for the 10 px slot in an app with the battle command grid); characters outside the preview budget show as boxes in the preview only; the kit's fixed words are English unless the game replaces them (`uiText`, below); no input method (name input is a Latin keyboard). See [Chinese (CJK) text](../README.md#chinese-cjk-text) |
| Replaceable interface words (`uiText`): the kit's own words in another language | Done | Every word the kit draws (legend labels, shop box, save menu and its runtime save/load feedback, name-input caption and action cells, attract and demo chrome, event-error title, `StatBar` readout) is a key with an English default; a game sets any subset in `Project.uiText` (per language shard; editor and Studio validate it and `editor/api` patches edit it, no form yet; the Studio play-test shows it) or GameView's `uiText` prop, which switches language at run time. Sentences use named placeholders and wrap after filling. The table is presentation only: never in state or saves, and excluded from a sharded shell's map manifest hash, so a save loads across shards that differ only in their interface words (per-language map content still changes the identity). Every key is exercised at its schema limit on the page that displays it, and every path stays inside 480x272: the 248 px shop/choice box caps at 166 px, the 420 px save panel grows from 232 to at most 256 px, and the 430 px demo panel caps at 256 px. Their row lists use the remaining pixel budget and retain the selected item. Chrome cells wrap to a page-specific row limit, then marquee from offset zero to exactly the measured overflow (one pixel per two ticks, with a 45-tick hold at each edge), so both ends remain reachable; changing text or width reselects wrap versus marquee without a remount. Fixed cells (name-input actions, a reserved `StatBar` cell) use the wrap-to-10-px-to-focused-scroll ladder. Limits: an event error's interpreter message and a demo error's arbitrary exception text stay developer English (the demo's own fixed error sentences are templates); the default player name is `Project.playerName`. See [Interface words](../README.md#interface-words-uitext) |
| Dialog themes and speaker portraits | Done | [Themes and speaker portraits](../README.md#themes-and-speaker-portraits) |
| Text box position, alignment and background | Done | A `text` command may place its box in the top, centre or bottom band, a corner or a side (`position`), align its rows left/centre/right (`align`) and top/centre/bottom (`valign`), and draw it framed, dimmed or transparent (`background`). The bands keep the RPG Maker box (full width less 8 px a side, 92 px, four rows); corner and side boxes are Tuxemon's small dialog window, 0.8 of the screen wide and 0.25 high, flush with their edges (384x68 at 480x272, 768x136 at 960x544), and their pages are cut at that width and row count, so long text continues on more pages and never cuts. A text without the fields draws the same box as before. The RPG Maker importer maps Show Text position and background; the editor and Studio edit all four, labelled in Chinese and English. Limits: no Tuxemon `large_gui` size; on a screen shorter or narrower than 480x272 a page that needs more rows grows the window; Tuxemon draws its avatar outside the window, the kit draws it inside; a portrait or name tab keeps the theme's colours on a dim or transparent box; words keep the theme's ink colour on every background (no outline on a transparent box). See [Text box layout](../README.md#text-box-layout) |

## Saves, rewind and demos

| Feature | Status | Notes |
| --- | --- | --- |
| Save slots and save codes | Done | Slots use `data.fs` on desktop; the web falls back to save codes. Loaded snapshots are validated. Save codes are DEFLATE-compressed (about 2× shorter for a small game, 4–6× for a large one) and the older uncompressed codes still load. See [Saves and save codes](../README.md#saves-and-save-codes) |
| Silent autosave and read-only automatic slot | Done | `{op:"autosave"}` publishes a detached snapshot at its reference tick when v1 can resume the state, including open modals, running fibers, movement and waited routes. During an active scene/handoff/fade-out, fatal interpreter state or unconsumed transfer/battle/scene request, autosaves coalesce and publish once at the first resumable reference tick; manual save remains unavailable while one is pending. Missing callbacks are no-ops, `saveAccess` does not suppress autosave, and attract rewind/refold does not repeat the host write. Desktop uses `save/autosave.json`; the web bridge uses an app-scoped browser-storage key; sim has an in-memory bridge. `SaveMenu` lists a present automatic save first on load pages, including web hosts without manual slots, and never offers it as a save target. See [Saves and save codes](../README.md#saves-and-save-codes) |
| Saves keep the current map's characters | Done | A save records where every character on the current map stands and faces, its running and patrol move routes with their progress (including a path search in flight), the wander RNG, a route running on the player and a post-transfer fade-in, so a load continues frame for frame mid-scene. Loads refuse character fields that disagree with each other (a step off the map, a pixel position away from the tile) and save data too large (over 16 MiB of UTF-8 envelope JSON) or too deeply nested. Saves made before this still load; their characters start again from the map |
| Loading a save into a running GameView | Done | The `overlay` prop gives a game's menu live session access; `saveFromView` / `loadIntoView` (`pocket-rpgkit/ui/saves`) save and load with typed error codes and leave the game untouched on refusal. It turns on no attract controller, so L does not rewind; beside a demo, a save records the buttons the demo was holding. See [Saves and save codes](../README.md#saves-and-save-codes) |
| Sharded projects and saves across schema updates | Done | Shells and saves made under an earlier schema version load as long as every change since then only added optional fields, commands or conditions; a change to existing behaviour refuses them until a migration exists (none ships yet). The four additive predecessors before KRM2 commands, loops/event touch, world layouts and optional choice icons are accepted; older versions predate behaviour changes and are refused with a message naming the accepted versions. Saves are rewritten under the current version. See [Schema identities](../src/data/CHANGELOG.md#schema-identities) |
| Attract mode | Done | Plays a tape after 10 idle seconds; any button takes over, **L** rewinds 3 virtual seconds, using keyframes capped by size (2 MiB) and count (64). Under `immutableState` keyframes share the published states instead of copying them, so a large game keeps its heap close to the demo-off level; games tune the limits with `DemoOptions.rewind`. See [Attract rewind keyframes](../README.md#attract-rewind-keyframes) |
| Demo controls and web deep links | Done | Opt-in chapter starts, safe map warp and 1×/2×/4× autoplay through [`pocket-rpgkit/ui/demo`](../README.md#demo-controls-pocket-rpgkituidemo); chapters can share one recorded tape by window, load it lazily from a provider that is resolved once, and resume on the recording's global frame; web chapter cards support preview images and descriptions, jump the running game without a reload, and retain query-link fallbacks. Desktop has the menu but no guest argv/environment launch bridge |
| Byte-identical replays on every host and simulation rate | Done | No wall clock and no `Math.random` in the engine |

The driver receives a component-world camera (the same space as the world renderer's `cameraFor`), so the origin is applied exactly once; the contract is documented in `world-contract.ts`.
